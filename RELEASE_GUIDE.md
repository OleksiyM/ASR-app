# ASR-app: Инструкция по созданию релизов 🚀

Этот гайд описывает шаги, которые необходимо выполнить для сборки, тестирования и выпуска новой версии приложения **ASR-app**, чтобы все обновления корректно отображались у пользователей и на сайте-лендинге.

---

## 📋 Чек-лист релиза (Release Checklist)

При подготовке новой версии (например, `1.2.6`), выполните следующие шаги по порядку:

### 1. Подготовка версии в коде
* **Файл `project.yml`**:
  * Измените `MARKETING_VERSION` на новую версию (например, `1.2.6`).
  * Увеличьте `CURRENT_PROJECT_VERSION` (номер сборки/билда) на единицу (например, с `1` до `2`).
* **Генерация проекта**:
  * В терминале в корне проекта выполните команду для пересборки Xcode-файлов:
    ```bash
    xcodegen
    ```
* *Примечание*: В окне «О программе» (`AboutView.swift`) номер версии теперь считывается **динамически** из `Info.plist` (через `CFBundleShortVersionString`). Вручную в коде SwiftUI менять версию больше **не нужно**!

---

### 2. Сборка приложения и DMG
* Соберите релизные версии приложения (`.app`) под обе архитектуры:
  * **Apple Silicon (M-series)**: архитектура `arm64`
  * **Intel**: архитектура `x86_64`
* Упакуйте собранные приложения в DMG-архивы с именами:
  * `ASR-App-AppleSilicon.dmg`
  * `ASR-App-Intel.dmg`

---

### 3. Публикация релиза на GitHub
* Запушите все изменения в ветку `main`.
* Создайте новый git-тег для релиза (версия должна начинаться с буквы `v`):
  ```bash
  git tag v1.2.6
  git push origin v1.2.6
  ```
* Зайдите на GitHub репозиторий в раздел **Releases** и создайте новый релиз на основе созданного тега `v1.2.6`.
* **Важно**: Прикрепите оба созданных DMG-файла (`ASR-App-AppleSilicon.dmg` и `ASR-App-Intel.dmg`) к релизу в качестве прикреплённых ассетов (Assets).

---

### 4. Обновление метаданных автообновления
Файл метаданных находится по пути `docs/version.json`. Отредактируйте его:
```json
{
  "latestVersion": "1.2.6",
  "build": 4,
  "requiredOS": "14.0",
  "urls": {
    "arm64": "https://github.com/OleksiyM/ASR-app/releases/download/v1.2.6/ASR-App-AppleSilicon.dmg",
    "x86_64": "https://github.com/OleksiyM/ASR-app/releases/download/v1.2.6/ASR-App-Intel.dmg"
  },
  "releaseNotes": {
    "en": "Short description of what's new in English.",
    "ru": "Краткое описание нововведений на русском.",
    "uk": "Короткий опис нововведень українською."
  }
}
```
* **`latestVersion`**: Укажите точную строку новой версии (например, `"1.2.6"`).
* **`build`**: Укажите номер билда, совпадающий с `CURRENT_PROJECT_VERSION` из `project.yml`.
* **`urls`**: Замените тег в путях скачивания на новый (например, `/v1.2.6/`). Эти ссылки должны вести на ассеты релиза, созданного на предыдущем шаге.
* **`releaseNotes`**: Запишите краткий список изменений на трёх языках.

---

### 5. Публикация изменений на сервере
После редактирования файла `docs/version.json`, закоммитьте и отправьте его в репозиторий:
```bash
git add docs/version.json project.yml
git commit -m "chore: release version 1.2.6 and update version metadata"
git push origin main
```

---

## ⚡️ Как это работает автоматически?
Благодаря нашей архитектуре, после пуша `version.json` в `main`:
1. **Сайт-лендинг (`docs/index.html`)** автоматически подтянет новые ссылки и номер версии с помощью JavaScript, пользователям на сайте сразу станет доступна кнопка скачивания новой версии.
2. **Фоновый чекер обновлений** у пользователей, у которых установлена предыдущая версия (например, `1.2.5`), бесшумно обратится по адресу `https://oleksiym.github.io/ASR-app/version.json`, обнаружит, что `1.2.6` > `1.2.5`, и красиво покажет оранжевый баннер в поповере и статус в окне About со ссылкой на скачивание нового DMG.
